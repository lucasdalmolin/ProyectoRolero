# Roadmap

El roadmap es incremental. Las etapas no equivalen a fechas comprometidas. El orden siguiente refleja la secuencia de planificación acordada; el orden de implementación puede ajustarse al validar riesgos.

| Etapa | Objetivo | Estado |
|---|---|---|
| 1. Visión del producto | Identidad, público y principios | Completada |
| 2. Inventario y alcance del MVP | Delimitar y aprobar las cinco funcionalidades | **Completada — punto de control 02** |
| 3. UX y recorridos de usuario | Navegación, flujos de principiantes, estados y prototipos | **Completada para iniciar desarrollo; iterativa** |
| 4. Dominio y contenido | Entidades, contenido, motor del test, ediciones y licencias | Pendiente |
| 5. Arquitectura técnica | Módulos, persistencia, stack y despliegue | **En curso** |
| 6. Diseño e implementación | Desarrollo incremental de las cinco herramientas | Pendiente |
| 7. Validación y lanzamiento | Pruebas con principiantes, accesibilidad, revisión y publicación | Pendiente |

## Propuesta de incrementos de implementación (no aprobada como cronograma)
1. Base de navegación y componentes compartidos.
2. Introducción al rol y Cómo funciona una partida.
3. Guía de dados y Conceptos y reglas básicas.
4. Test Vocacional: prototipo de afinidades, cuestionario y resultados.
5. Integración, pruebas y publicación.

Un prototipo temprano del motor del test podría reducir riesgo sin alterar el alcance aprobado.
